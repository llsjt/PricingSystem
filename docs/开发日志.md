# 开发日志

本文用于记录电商智能定价平台的开发过程、关键技术演进、跨端协作边界和后续风险。它面向毕业设计答辩和后续维护，重点说明项目如何从早期原型逐步演进到“前端 + Java 后端 + Python Worker + MySQL + RabbitMQ”的完整链路。

本文不替代以下文档：

- `README.md`：项目入口、功能概览和运行说明
- `技术栈.md`：前端、Java、Python、数据库和部署技术栈
- `docs/API文档.md`：接口说明
- `ops/`：Public Beta 部署、压测、告警、备份和回滚手册

## 维护规则

- 新开发记录追加到“阶段化开发日志”中，必要时拆分新阶段。
- 每条记录必须以真实提交、文件变更、迁移脚本或运行记录为依据。
- 涉及数据库结构时，写明对应 `database/migration_*.sql`。
- 涉及接口、SSE、任务状态或消息队列时，说明前端、Java 后端、Python Worker 的协作关系。
- 只记录真实完成或真实验证过的内容，不补写用户量、性能指标、上线结论或外部平台能力。

## 当前系统基线

- 前端使用 Vue 3 + TypeScript + Vite，通过 `/api/**` 访问 Java 后端。
- Java 后端使用 Spring Boot 3.2 + Java 21，对外提供鉴权、商品、店铺、定价任务、批量定价、SSE 和健康检查接口。
- Python Worker 使用 FastAPI + CrewAI，作为内部智能定价执行服务，不直接暴露给浏览器。
- MySQL 保存商品、SKU、任务、Agent 日志、定价结果、批量任务、用户模型配置和会话数据。
- RabbitMQ 承担 Java 到 Python 的异步任务派发，Python Worker 消费任务后写入 MySQL，Java 再读取并通过 SSE 推送给前端。
- Public Beta 相关部署和运维材料集中在 `docker-compose.public-beta.yml`、`scripts/` 和 `ops/`。

## 开发主线概览

项目开发主线可以概括为七个阶段：

1. 搭建原型和基础定价链路，形成商品、用户、前端页面和本地定价服务雏形。
2. 打通商品导入、字段映射和 Python 多 Agent 后端，开始替换 Java 伪 Agent。
3. 接入 CrewAI、SSE 和 4-Agent 卡片流，让定价过程可以被前端实时展示。
4. 补齐认证、安全、UI、商品状态和用户级模型配置，为公测和多用户使用做准备。
5. 收敛定价策略、竞品来源和 Agent 输出质量，并支持失败节点重试。
6. 扩展批量定价和 RabbitMQ 异步执行架构，解决单商品链路难以承载批量任务的问题。
7. 补齐 Public Beta 部署工件、API 文档、展示截图和吞吐配置，提升交付和维护完整度。
